## WHY IT HAPPENS -- A TRUE FACT LED TO THE BUG
   dcrt0.cc:1046-1060.  x86_64 does:
        movq %[ADDR],%rsp ; movq %rsp,%rbp ; subq ,%rsp
   The aarch64 arm does:
        mov sp,%[ADDR] ; mov x29,sp
   with the comment "Windows ARM64 has no shadow space, so unlike x86_64
   nothing has to be subtracted here."
   THAT PREMISE IS TRUE AND THE CONCLUSION IS WRONG.  The x86 'subq ' is
   documented as shadow space, but it ALSO buys headroom below the stack top.
   x86_64 addresses locals at NEGATIVE offsets from rbp, so it stays below
   stackaddr regardless.  AArch64 addresses spills at POSITIVE offsets from
   sp.  With sp = StackBase-16 there are only 16 bytes before the cygheap,
   and the compiler's spill of the TEB across the VirtualFree call reaches
   offsets 24..31 -- i.e. 8..15 bytes PAST StackBase, straight into
   cygheap->chain.  Reach 32 bytes vs 16 available.
