## B. "ch_spawn IS A NO_COPY STATIC CARRYING A STALE parent HANDLE" -- REFUTED.
   Candidate: child_info_spawn NO_COPY ch_spawn (spawn.cc:275) is a static,
   so its parent handle might have been duplicated in a prior context and
   reused -- which would explain a non-zero but invalid handle.
   FIRST, STATIC: the default ctor is EMPTY -- "child_info_spawn () {};"
   (child_info.h) -- so nothing is minted at static-init.  The real ctor runs
   via placement new in set(): "new (this) child_info_spawn (ci, b)".
   THEN, MEASURED, by instrumenting BOTH ends (mint site in sigproc.cc and
   the child's read in dcrt0.cc):
     CTOR:  type=1 parent=0x190 minted_in_pid=14816 this=0x7FF96D6FE270
     CHILD: got parent=0x190 usable=0 err=6 my_pid=24068 parent_winpid=14816
   READING: the value the child receives (0x190) is EXACTLY the value minted,
   the minting pid (14816) EQUALS parent_winpid, and the mint happened for
   THIS spawn (type=1).  The handle is FRESH, minted in the CORRECT process,
   and TRANSMITTED INTACT -- and still invalid in the child.
   => The stale/reused-handle hypothesis is DEAD.
