## EDIT 2 -- cygwin.sc.in, above the ctor/dtor conditional
  Records why __aarch64__ must stay in the condition: the #else branch is the
  legacy 32-bit form with 4-byte LONG markers and no ALIGN(8), and an 8-byte
  read straddles the ctor terminator and dtor head marker yielding exactly
  0xFFFFFFFF00000000. Includes the measured symbol arithmetic (pre-fix
  __DTOR_LIST__ at 0x180217EFC = 4 mod 8, post-fix 0x180217F00) and the point
  that THE LINKER VALIDATES NOTHING HERE -- 4-byte and even deliberately wrong
  12-byte markers both link cleanly, so only execution distinguishes them.

## EDIT 3 -- cygwin.sc.in, above the .xdata guard
  Records that without __aarch64__ the placement falls to the linker's
  orphan-section heuristic; that it happened to work but was luck; that it is
  load-bearing because __unwind_single_frame uses RtlLookupFunctionEntry and
  RtlVirtualUnwind which read .xdata; and that making it explicit DOES change
  the image (orphan placement put .xdata before .pdata, the rule puts it
  after), which is why it was re-verified after the change.
