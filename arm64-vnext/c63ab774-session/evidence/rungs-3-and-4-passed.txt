## THE BUG THAT BLOCKED THEM: import_address() DECODES x86 MACHINE CODE
  mm/malloc_wrapper.cc:49
      if (*((uint16_t *) imp) == 0x25ff)     /* x86 FF 25 = jmp *disp32(%rip) */
        { ...decode a RIP-relative displacement... }

  THERE IS NO ARCHITECTURE GUARD AT ALL. It is a bare magic number, which is
  why every #ifdef and $cpu sweep missed it -- there is nothing to grep for.
  This is the FIFTH instance of an x86 assumption in the port and the first
  that is invisible to a conditional-compilation search.

  On AArch64 mkimport emits
      adrp x16, __imp_sym ; ldr x16, [x16, #:lo12:__imp_sym] ; br x16
  so the first two bytes are never 0x25ff and import_address always returns
  NULL. Then in malloc_init:
      use_internal = user_data->malloc == malloc
                     || import_address ((void *) user_data->malloc) == &_sigfe_malloc;
  user_data->malloc is the APP'S IMPORT THUNK, not the DLL's malloc, so the
  first test fails; import_address returns NULL, so the second fails;
  use_internal stays FALSE. Every malloc/calloc/free then does
  user_data->malloc(...) -> the app's thunk -> back into the DLL's malloc ->
  !use_internal -> user_data->malloc(...) -> ... UNBOUNDED RECURSION.

## HOW IT WAS PROVEN, NOT GUESSED
  Win32 debug API capture (DEBUG_ONLY_THIS_PROCESS + WaitForDebugEvent +
  GetThreadContext), modules resolved with VirtualQueryEx at fault time:
     0xC00000FD STACK_OVERFLOW
     PC = msys-2.0.dll RVA 0xAFBA0     SP 16-byte aligned: YES
     LR = msys-2.0.dll RVA 0xAFBD8
  RVA 0xAFBA0 is calloc+0x4, a stack-clash probe:
     1800efb9c <calloc>:  sub x10, sp, #0x2, lsl #12
     1800efba0:           str xzr, [x10, #4032]   <== FAULTED
  LR at calloc+0x3C is the return address of the 'blr x2' INSIDE calloc, so
  control came back round into calloc's own prologue -- self-recursion, with
  the stack probe merely the first instruction to notice.
  Then measured statically: the pointer calloc branches through, at
  __cygwin_user_data+0x78 (VA 0x18021EB38), holds 0x1800EFB9C == calloc.

## THE FIX
  Teach import_address to decode the AArch64 thunk:
     adrp x16,X    (insn & 0x9f00001f) == 0x90000010, imm21 = immhi:immlo << 12
     ldr x16,[x16] (insn & 0xffc003ff) == 0xf9400210, offset = imm12 * 8
     br  x16       == 0xd61f0200
  recover the IAT slot address and read the target. x86 path left untouched
  under #else, so no x86_64 behaviour changes.
