## THE BUG: 32-BIT CTOR/DTOR LIST MARKERS ON A 64-BIT TARGET
  winsup/cygwin/cygwin.sc.in builds the constructor/destructor lists as:

    #ifdef __x86_64__
        . = ALIGN(8);
        ___CTOR_LIST__ = .;  LONG(-1); LONG(-1); *(.ctors) ... LONG(0); LONG(0);
        ___DTOR_LIST__ = .;  LONG(-1); LONG(-1); *(.dtors) ... LONG(0); LONG(0);
    #else
        ___CTOR_LIST__ = .;  LONG(-1);            *(.ctors) ... LONG(0);
        ___DTOR_LIST__ = .;  LONG(-1);            *(.dtors) ... LONG(0);
    #endif

  LONG is 4 BYTES. x86_64 emits TWO of them for 8-byte head markers and
  terminators, matching 64-bit function pointers, and aligns to 8.
  THE #else BRANCH IS THE LEGACY 32-BIT PATH -- AND AARCH64 FELL INTO IT.
  So the ARM64 build got 4-byte markers and no 8-byte alignment.

## HOW IT WAS FOUND -- BY CAPTURING x30, NOT THE FAULT TARGET
  Earlier captures recorded only the faulting address, which was garbage and
  led nowhere. Capturing the FULL ARM64 CONTEXT and resolving modules with
  VirtualQuery AT FAULT TIME (never an assumed ImageBase) gave:

    ACCESS_VIOLATION EXECUTE target=0xFFFFFFFF00000000
    PC = 0xFFFFFFFF00000000                       UNMAPPED
    LR = 0x00007FFDB10B83B8   msys-2.0.dll base=0x7FFDB10B0000 RVA=0x83B8
    x0 = 0xFFFFFFFF00000000   <- held the faulting target

  RVA 0x83B8 is the return address, so the branch is at RVA 0x83B4:

    1800483a8:  cmp  x19, x20
    1800483ac:  b.ls 1800483c0
    1800483b0:  ldr  x0, [x19], #-8      // walk the list backwards
    1800483b4:  blr  x0                  // <== FAULTED
    1800483b8:  cmp  x19, x20

  A backwards constructor-list walk. With 4-byte markers the 8-byte reads
  straddle the ctor terminator LONG(0) and the dtor head marker LONG(-1):
      [00 00 00 00][FF FF FF FF]  ->  0xFFFFFFFF00000000
  EXACTLY the captured target. Diagnosis and observation agree bit for bit,
  and this finally explains the value that had been unexplained all session.

## THE FIX
  cygwin.sc.in:27   #ifdef __x86_64__
                 -> #if defined(__x86_64__) || defined(__aarch64__)
  One line. aarch64 now gets 8-byte markers and ALIGN(8), same as x86_64.
