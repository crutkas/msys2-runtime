## BUG FOUND AND FIXED BY EXECUTING: Windows ARM64 TEB register
  winsup/cygwin/include/cygwin/config.h __getreent() read the TEB with
      mrs xN, tpidr_el0 ; ldr xN, [xN, #8]
  under a comment asserting 'On Windows ARM64 the TEB pointer is held in
  tpidr_el0 (and mirrored in the reserved platform register x18)'.
  THAT IS BACKWARDS.

  EMPIRICAL PROOF, measured on this machine by executing raw AArch64
  instructions in allocated RWX memory (no compiler required):
      mrs x0, tpidr_el0  -> 0x0000000000000000     <-- ZERO
      mov x0, x18        -> 0x00000080002C8000
      [x18+0x08] StackBase = 0x000000801B990000
      GetCurrentThreadStackLimits high = 0x000000801B990000   MATCH
  x18 IS the TEB; tpidr_el0 is zero. So 'ldr xN,[xN,#8]' reads address 0x8.
  The first captured fault was AV READ of target 0x0000000000000008 -- exact match.

  FIXED in two places (tpidr_el0 -> x18, read-only, never written):
    - include/cygwin/config.h  __getreent()
    - scripts/gendef           6 trampoline emission sites
  newlib was ALSO rebuilt, because the preserved libc.a/libm.a carried
  inlined __getreent copies compiled against the old header.
  Result: tpidr_el0 occurrences in the linked DLL 520 -> 0; x18 sites 1850.
