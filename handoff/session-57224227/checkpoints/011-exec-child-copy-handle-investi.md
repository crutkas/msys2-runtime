<technical_details>
- **DEFECT #1 (FIXED, verified): cygheap chain corruption.** `str x4,[sp,#24]` @ RVA 0x6CD8 in `_dll_crt0`. Incidental compiler spill of TEB (x4=x18) live across `VirtualFree(NtCurrentTeb()->DeallocationStack)` (dcrt0.cc:1067). `sp = StackBase-16`, so `[sp,#24] = StackBase+8 = cygheap+8 = cygheap->chain` via exact-by-construction StackBase≡cygheap-base aliasing at `0x800000000`. Cause: aarch64 arm (dcrt0.cc:1058-1061) drops x86_64's `subq $32,%rsp` (l1052); comment true about shadow space but subtraction also gave headroom; AArch64 spills at POSITIVE sp offsets. Fix: `sub sp,sp,#0x40` (64B; measured: max sp-relative reach 32 vs 16 available). Verified DLL sha256 `54e464d0…`.
- **DEFECT #2 (FIXED, verified): upstream strcpy-overlap.** dcrt0.cc `quoted()` l165/167 `strcpy(cmd,cmd+1)`/`strcpy(p,p+1)` = UB (C std 7.24.2.3). Linked aarch64 `strcpy` is NEON (`ld1 {v0.16b}`, `cmeq`, `shrn`, `ldr q0,[x2,#16]!`). x86 byte-forward masks it. Fix: `memmove` (behaviour-preserving: `memmove(dst,dst+1,strlen(dst+1)+1)` == intended strcpy semantics, so no x86 regression — the lead argument for any upstream filing). **This is the first NON-port defect — a latent upstream Cygwin bug the port exposes.** Committed `6397acaa5`.
- **DEFECT #2 bug ALSO corrupts exec target filenames** — pre-fix, `rung3.exe`→`runng3.exe`→ENOENT before `child_copy`. This explains the "error 6 is gone" false report (program died before the err6 code ran). c63ab774 resolved it one-variable-at-a-time: call form (execv/execl) is NOT the variable — the DLL (argv fix present/absent) is.
- **DEFECT #3 (LIVE, root cause NOT named): exec child_copy failure.** Fails at `mm/cygheap.cc:102` `child_copy(child_proc_info->parent, false, …)` in `cygheap_fixup_in_child(execed=true)`, reading cygheap `0x800000000..0x800025B30`, `done 0`, err6 (INVALID_HANDLE).
